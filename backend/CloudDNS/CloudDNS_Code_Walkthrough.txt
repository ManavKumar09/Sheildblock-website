# CloudDNS Backend Architecture: Code Walkthrough

This document provides a detailed, line-by-line explanation of every file we created in your `backend/CloudDNS` folder. The architecture is modular, meaning different responsibilities (database, logic, API routing) are split into separate files to keep the code clean and maintainable.

---

## 1. `db.py` (Database Configuration)
This file handles the connection between your Python app and the actual SQLite (or future PostgreSQL) database using SQLAlchemy.

```python
import os
from sqlalchemy import create_engine
from sqlalchemy.orm import declarative_base
from sqlalchemy.orm import sessionmaker
from dotenv import load_dotenv

# Loads the variables from your .env file into Python's environment
load_dotenv()

# Grabs the DATABASE_URL from .env. If it's missing, it defaults to a local file named 'shieldblock.db'
DATABASE_URL = os.getenv("DATABASE_URL", "sqlite:///./shieldblock.db")

# Creates the SQLAlchemy "engine", which is the core object that talks to the database.
# The 'check_same_thread' argument is a specific requirement for SQLite to allow multiple requests to read/write at once.
engine = create_engine(
    DATABASE_URL, connect_args={"check_same_thread": False} if "sqlite" in DATABASE_URL else {}
)

# Creates a factory for generating database sessions. A session is a temporary workspace for your queries.
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)

# Creates a base class. All our database models (like User) will inherit from this class so SQLAlchemy knows they are tables.
Base = declarative_base()

# A "dependency" function. Every time an API request needs to talk to the DB, it calls this to get a session,
# and guarantees the session is closed safely when the request is done.
def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

## 2. `models.py` (Database Tables)
This file defines the actual structure of your database tables using Python classes.

```python
import uuid
from sqlalchemy import Column, String, Boolean
from db import Base

# Creates a User class that inherits from 'Base' (linking it to SQLAlchemy)
class User(Base):
    # Tells SQLAlchemy the actual name of the table in the database will be "users"
    __tablename__ = "users"

    # Creates a column named 'id'. It is a String, acts as the Primary Key, is indexed for fast lookups.
    # It automatically generates a unique UUID (like "123e4567-e89b-12d3...") whenever a new user is created.
    id = Column(String, primary_key=True, index=True, default=lambda: str(uuid.uuid4()))
    
    # Creates a 'name' column.
    name = Column(String, index=True)
    
    # Creates an 'email' column. It must be unique (no two users can have the same email).
    email = Column(String, unique=True, index=True)
    
    # Stores the encrypted password. We never store plain-text passwords for security.
    hashed_password = Column(String)
    
    # A true/false flag to track if the user has clicked the email verification link. Defaults to False.
    is_verified = Column(Boolean, default=False)
```

## 3. `schemas.py` (Data Validation)
While `models.py` defines the database, `schemas.py` defines the API inputs and outputs using Pydantic. It ensures the data sent to and from your React frontend is perfectly formatted.

```python
from pydantic import BaseModel, EmailStr

# Defines the exact structure we expect when the React frontend sends a Sign-Up request
class UserCreate(BaseModel):
    name: str
    email: EmailStr # EmailStr automatically verifies that the text contains an '@' and a valid domain
    password: str

# Defines the exact structure we send BACK to the frontend after a successful request
class UserResponse(BaseModel):
    id: str
    name: str
    email: EmailStr
    is_verified: bool
    # Notice we DO NOT include the password here. This prevents accidentally leaking passwords to the frontend.

    class Config:
        # Tells Pydantic to read data from SQLAlchemy objects directly, converting them to JSON automatically
        from_attributes = True 
```

## 4. `users.py` (Business Logic)
This file contains the core logic for manipulating user data, keeping the API endpoints clean.

```python
import bcrypt
from sqlalchemy.orm import Session
from models import User
from schemas import UserCreate

# Function to safely encrypt a password
def get_password_hash(password: str):
    # Converts the plain string into raw bytes
    pwd_bytes = password.encode('utf-8')
    # Generates a random "salt" (random data added to the password before hashing for extra security)
    salt = bcrypt.gensalt()
    # Hashes the password mathematically
    hashed_password = bcrypt.hashpw(pwd_bytes, salt)
    # Converts it back to a readable string to save in the database
    return hashed_password.decode('utf-8')

# Function to find a specific user in the database by their email address
def get_user_by_email(db: Session, email: str):
    return db.query(User).filter(User.email == email).first()

# Function to save a new user to the database
def create_user(db: Session, user: UserCreate):
    # 1. Encrypts their password
    hashed_password = get_password_hash(user.password)
    # 2. Creates the SQLAlchemy User object
    db_user = User(
        name=user.name, 
        email=user.email, 
        hashed_password=hashed_password
    )
    # 3. Stages the user to be saved
    db.add(db_user)
    # 4. Commits (saves) the changes to the database
    db.commit()
    # 5. Refreshes the object so we get the auto-generated UUID
    db.refresh(db_user)
    return db_user

# Function to flip the 'is_verified' switch to True
def verify_user(db: Session, email: str):
    user = get_user_by_email(db, email)
    if user:
        user.is_verified = True
        db.commit()
        db.refresh(user)
    return user
```

## 5. `email_utils.py` (Email & Tokens)
This file handles generating secure email verification links and actually sending the emails.

```python
import os
from fastapi_mail import FastMail, MessageSchema, ConnectionConfig, MessageType
from jose import jwt
from datetime import datetime, timedelta
from dotenv import load_dotenv

load_dotenv()

# Grabs secrets used to cryptographically sign the tokens
SECRET_KEY = os.getenv("SECRET_KEY", "fallback_secret")
ALGORITHM = os.getenv("ALGORITHM", "HS256")

# Configures the SMTP server (Gmail) using variables from your .env
conf = ConnectionConfig(
    MAIL_USERNAME=os.getenv("MAIL_USERNAME"),
    MAIL_PASSWORD=os.getenv("MAIL_PASSWORD"),
    MAIL_FROM=os.getenv("MAIL_FROM"),
    MAIL_PORT=int(os.getenv("MAIL_PORT", 587)),
    MAIL_SERVER=os.getenv("MAIL_SERVER", "smtp.gmail.com"),
    MAIL_FROM_NAME=os.getenv("MAIL_FROM_NAME", "ShieldBlock"),
    MAIL_STARTTLS=True,
    MAIL_SSL_TLS=False,
    USE_CREDENTIALS=True,
    VALIDATE_CERTS=True
)

# Generates a unique, encrypted token containing the user's email
def create_verification_token(email: str):
    # The token will expire and become useless in exactly 24 hours
    expire = datetime.utcnow() + timedelta(hours=24)
    # Data to hide inside the token
    to_encode = {"exp": expire, "sub": email}
    # Uses your SECRET_KEY to lock and sign the token
    encoded_jwt = jwt.encode(to_encode, SECRET_KEY, algorithm=ALGORITHM)
    return encoded_jwt

# Reads the token back to find out which email it belongs to
def decode_verification_token(token: str):
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        email: str = payload.get("sub")
        return email
    except Exception:
        # Returns nothing if the token is tampered with or expired
        return None

# The function that constructs and fires off the actual email
async def send_verification_email(email: str, token: str):
    # Constructs the link they will click
    verification_link = f"http://localhost:8000/verify/{token}"
    
    # Basic HTML content of the email
    html = f"""
    <p>Welcome to ShieldBlock!</p>
    <p>Please click the link below to verify your email address:</p>
    <p><a href="{verification_link}">{verification_link}</a></p>
    """
    
    # Prints to terminal so you can test locally without an email server
    print(f"\n=============================")
    print(f"Mock Email to {email}:")
    print(f"Verification Link: {verification_link}")
    print(f"=============================\n")

    # If you put a real email in .env, it packages up the email and sends it
    if os.getenv("MAIL_USERNAME") and os.getenv("MAIL_USERNAME") != "your_test_email@gmail.com":
        message = MessageSchema(
            subject="ShieldBlock - Verify your Email",
            recipients=[email],
            body=html,
            subtype=MessageType.html
        )
        
        fm = FastMail(conf)
        try:
            await fm.send_message(message)
            print(f"Verification email actually sent to {email} via SMTP.")
        except Exception as e:
            print(f"Failed to send email to {email} via SMTP. Error: {e}")
```

## 6. `main.py` (API Endpoints)
This is the entry point of your application. It ties all the other files together and exposes URLs to the web.

```python
from fastapi import FastAPI, Depends, HTTPException, status
from sqlalchemy.orm import Session
from db import engine, Base, get_db
import models
import schemas
import users
from email_utils import create_verification_token, send_verification_email, decode_verification_token

# Connects to SQLite and actually creates the 'users' table if it doesn't exist yet
Base.metadata.create_all(bind=engine)

# Initializes the FastAPI framework
app = FastAPI(title="ShieldBlock API")

# Creates the POST /register route. It expects 'schemas.UserCreate' as input and outputs 'schemas.UserResponse'
@app.post("/register", response_model=schemas.UserResponse)
async def register(user: schemas.UserCreate, db: Session = Depends(get_db)):
    # Checks if the email already exists in the database
    db_user = users.get_user_by_email(db, email=user.email)
    if db_user:
        # Stops the request and sends a 400 error back to the frontend
        raise HTTPException(status_code=400, detail="Email already registered")
    
    # Saves the new user to the database
    new_user = users.create_user(db=db, user=user)
    
    # Creates the token and sends the email
    token = create_verification_token(new_user.email)
    await send_verification_email(new_user.email, token)
    
    # Returns the user data (stripping the password) back to the frontend
    return new_user

# Creates the GET /verify/{token} route. The {token} part is dynamic.
@app.get("/verify/{token}")
async def verify_email(token: str, db: Session = Depends(get_db)):
    # Decodes the token. If it's expired or invalid, it returns None.
    email = decode_verification_token(token)
    if not email:
        raise HTTPException(status_code=400, detail="Invalid or expired token")
        
    # Finds the user in the database
    db_user = users.get_user_by_email(db, email=email)
    if not db_user:
        raise HTTPException(status_code=404, detail="User not found")
        
    # Checks if they already clicked it in the past
    if db_user.is_verified:
        return {"message": "Email already verified."}
        
    # Updates the database to mark them as verified
    users.verify_user(db, email)
    return {"message": "Email successfully verified!"}
```
